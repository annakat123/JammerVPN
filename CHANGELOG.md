# История изменений

## 2026-11-04 — автономное подключение и совместимость с локальным прокси

Исправлен [issue #1](https://github.com/annakat123/JammerVPN/issues/1): после закрытия Happ приложения с сохранённым адресом локального HTTP-прокси, включая Codex, могли терять доступ через Jammer. Пользователь подтвердил работу актуальной версии.

### Основные изменения

- **Работа без Happ — `LocalProxy.cs`.** Jammer обслуживает свободный локальный HTTP-порт из Windows `ProxyServer`. Поддержаны HTTP/1.0–1.1 и HTTPS CONNECT; TLS передаётся без расшифровки. Исходящие TCP-соединения привязаны к IPv4-адресу и интерфейсу JammerTun.
- **Сохранение настроек Windows — `VpnConnection.cs`, `ProxyDiagnostics.cs`.** Убрано принудительное выключение и восстановление системного прокси. Занятый порт остаётся за существующим процессом; после освобождения Jammer может поднять собственный слушатель. При отключении освобождаются его порты и соединения.
- **Готовность подключения — `TunnelReadiness.cs`, `VpnConnection.cs`.** Статус подключения устанавливается после DNS-ответа через TUN. Проверка ожидает доступности нового Windows-адреса, устраняя немедленный сбой `SocketException 10049`; поддержаны отмена и общий тайм-аут 8 секунд.
- **Повторное подключение — `WinRoute.cs`.** Существующее исключение для VPN-сервера с подходящими интерфейсом и шлюзом используется повторно. При отключении удаляется только исключение, созданное текущей сессией.
- **Диагностика — `TunnelDiagnostics.cs`, `WinTun.cs`.** Добавлены счётчики чтения/передачи пакетов и ограниченные метаданные TCP/443 без содержимого пакетов. Обычный вывод netsh больше не помечается ошибкой.

### Проверки

- Release-сборка Windows проходит.
- Локальные TCP-проверки: HTTP, CONNECT с двусторонней передачей бинарных данных, сохранение данных сразу после заголовка, занятый и освобождающийся порт, отключение и повторный запуск.
- Проверки ожидания адреса Windows, отмены, тайм-аута и неизменности настроек прокси.
- Проверки обмена с тестовым сервером, некорректного ответа, ошибок TUN/маршрутов и очистки состояния соединения.
- Пользователь подтвердил работу обновления. Независимый захват авторизованной сессии Codex не выполнялся.

### Границы изменения

Совместимость относится к локальному HTTP-прокси; SOCKS, PAC и удалённые прокси не заменяются. Исправлен описанный сценарий, а не все возможные причины `workspace routing discovery failed`. Серверный протокол, шифрование и формат кадров этим блоком не менялись.
