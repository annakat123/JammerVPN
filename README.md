# JammerVPN

Рабочая версия Jammer для Windows с восстановленным TCP-подключением, сохранением настроек, русским/английским интерфейсом и журналированием.
Исходные проекты и автор: [Vimer5410](UPSTREAM.md). Лицензия ядра: [AGPL-3.0](LICENSE).

Описание актуального обновления, исправленного issue и выполненных проверок: [история изменений](CHANGELOG.md).

## Сборка

Нужны Windows и .NET SDK 9.0.320 (либо совместимый patch-релиз). Открыть `Jammer.Dev.sln` в Visual Studio или папку в VS Code.

```powershell
dotnet restore Jammer.Dev.sln
dotnet build Jammer.Dev.sln -c Release
dotnet publish source/Jammer-desktop/Jammer-desktop/Jammer-desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o build/JammerVPN
```

Запуск: двойным кликом `build/JammerVPN/Jammer-desktop.exe`. Программа сама запрашивает права администратора через стандартное подтверждение Windows. `wintun.dll` должна находиться рядом с exe и копируется при публикации.
Ввести IPv4 своего сервера. Сервер должен поддерживать исходный протокол Jammer TCP/7777.

## Что изменено

- `AppSettings.cs`, `HomeView`: один введённый IP сохраняется между запусками; адрес автора убран из GUI.
- `AppText.cs`, настройки и страницы: переключение RU/EN, сохранение языка, выравнивание длинных надписей.
- `AppLogging.cs`, `GuiLogSink.cs`, `LogView`: ежедневные файлы логов, переключатель записи, открытие журнала; история на главной сохраняется при навигации, прокручивается и имеет оформленный scrollbar.
- `VpnConnection.cs`, `HomeView`, `MainWindow`: восстановлены TCP/ECDH/AES и обмен пакетами, состояния кнопки, отключение и очистка; проверка IP, прав администратора и тайм-ауты подключения.
- `WinTun.cs`: безопасное закрытие дескрипторов, различение отсутствия пакетов и нативного сбоя, сохранение кода ошибки чтения/записи.
- `WinRoute.cs`: удаление исключения сервера на исходном интерфейсе; ошибка настройки маршрутов/DNS прерывает подключение; очистка продолжает работу при отсутствии отдельного правила.
- `Jammer-desktop.csproj`, `Jammer.Dev.sln`: журналирование в файл, доставка Wintun вместе с приложением, общее решение для GUI и ядра.

Настройки и логи находятся в `%LOCALAPPDATA%/JammerVPN`. В репозитории нет пользовательских конфигов, паролей, сетевых захватов и журналов.

## Проверка и границы

Release-сборка и локальные проверки обмена, отключения, некорректного ответа сервера, ошибки TUN и настройки маршрутов прошли:

```powershell
dotnet run --project tests/Jammer.Checks -c Release
```

Пользователь подтвердил работу актуального обновления. Исправлен сценарий потери доступа после закрытия локального HTTP-прокси Happ: [issue #1](https://github.com/annakat123/JammerVPN/issues/1). Это не означает устранение всех возможных причин ошибки workspace discovery; специального обхода сервисов Codex в коде нет.

## Системный прокси и TUN

Jammer не выключает и не восстанавливает настройки прокси Windows. После проверки туннеля он запускает совместимый локальный HTTP-прокси на свободных loopback-адресах из `ProxyServer`. HTTPS работает через CONNECT без расшифровки TLS. Внешние TCP-соединения привязаны к IPv4-адресу и интерфейсу JammerTun (`IP_UNICAST_IF`). Серверный протокол Jammer не менялся.

Соединение приложения с `127.0.0.1` остаётся на компьютере. Новые внешние IPv4-соединения работающего прокси используют обычную таблицу маршрутов, включая маршруты Jammer через TUN. Прокси с явной привязкой к другому интерфейсу, более специфические сторонние маршруты и уже открытые соединения требуют отдельной проверки. Наличие маршрутов Jammer само по себе не доказывает, что весь трафик Happ проходит через него.

Happ можно полностью закрыть: если его HTTP-порт свободен, оставшиеся обращения приложений к этому локальному адресу обслуживает Jammer. Если порт занят, Jammer оставляет работающий сервис нетронутым и проверяет освобождение порта раз в две секунды. При отключении Jammer его собственные слушатели и соединения закрываются. Это позволяет обслуживать также приложения, закэшировавшие адрес прокси, даже если `ProxyEnable` уже выключен.

Поддержаны HTTP/1.0–1.1 и HTTPS CONNECT; обычный HTTP обслуживается по одному запросу на соединение. SOCKS, PAC и удалённые адреса прокси этим механизмом не заменяются. Нет новых правил firewall, изменения реестра, установки сертификатов или перехвата TLS. Локальные проверки покрывают двустороннюю передачу бинарных данных, HTTP, занятой порт, освобождение порта и повторный запуск. Работу актуальной версии подтвердил пользователь; независимый захват авторизованной сессии Codex не выполнялся.

Проверка готовности ждёт, пока Windows позволит использовать назначенный TUN-адрес, и затем проверяет DNS через него; общий тайм-аут — 8 секунд. Ошибка `AddressNotAvailable` во время подготовки адреса больше не прерывает подключение немедленно.

Это фиксация выполненных исправлений, а не утверждение, что исправлены все дефекты проекта. Self-hosted исправлен для Linux x86_64 с systemd и nftables: см. [установку и проверки](SELF-HOSTED.md). Автозапуск и сворачивание в трей пока остаются элементами интерфейса. Серверный протокол, частичная отправка TCP и обработка переполнения серверной очереди в этой версии не менялись.
