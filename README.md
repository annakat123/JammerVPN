# JammerVPN

Рабочая версия Jammer для Windows с восстановленным TCP-подключением, сохранением настроек, русским/английским интерфейсом и журналированием.
Исходные проекты и автор: [Vimer5410](UPSTREAM.md). Лицензия ядра: [AGPL-3.0](LICENSE).

## Сборка

Нужны Windows и .NET SDK 9.0.320 (либо совместимый patch-релиз). Открыть `Jammer.Dev.sln` в Visual Studio или папку в VS Code.

```powershell
dotnet restore Jammer.Dev.sln
dotnet build Jammer.Dev.sln -c Release
dotnet publish source/Jammer-desktop/Jammer-desktop/Jammer-desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o build/JammerVPN
```

Запуск: `build/JammerVPN/Jammer-desktop.exe` от имени администратора. `wintun.dll` должна находиться рядом с exe и копируется при публикации.
Ввести IPv4 своего сервера. Сервер должен поддерживать исходный протокол Jammer TCP/7777.

## Что изменено

- `AppSettings.cs`, `HomeView`: один введённый IP сохраняется между запусками; адрес автора убран из GUI.
- `AppText.cs`, настройки и страницы: переключение RU/EN, сохранение языка, выравнивание длинных надписей.
- `AppLogging.cs`, `GuiLogSink.cs`, `LogView`: ежедневные файлы логов, переключатель записи, открытие журнала; история на главной сохраняется при навигации, прокручивается и имеет оформленный scrollbar.
- `VpnConnection.cs`, `HomeView`, `MainWindow`: восстановлены TCP/ECDH/AES и обмен пакетами, состояния кнопки, отключение и очистка; проверка IP, прав администратора и тайм-ауты подключения.
- `WinTun.cs`: безопасное закрытие дескрипторов, различение отсутствия пакетов и нативного сбоя, сохранение кода ошибки чтения/записи.
- `WinRoute.cs`: удаление исключения сервера на исходном интерфейсе; ошибка настройки маршрутов/DNS прерывает подключение; очистка продолжает работу при отсутствии отдельного правила.
- `Jammer-desktop.csproj`, `Jammer.Dev.sln`: журналирование в файл, доставка Wintun вместе с приложением, общее решение для GUI и ядра.

Настройки и логи находятся в `%LOCALAPPDATA%/JammerVPN`. В репозитории нет пользовательских конфигов, паролей, сетевых захватов и журналов.

## Проверка и границы

Release-сборка и локальные проверки обмена, отключения, некорректного ответа сервера, ошибки TUN и настройки маршрутов прошли:

```powershell
dotnet run --project tests/Jammer.Checks -c Release
```

Пользователь подтвердил, что проблема с Codex перестала воспроизводиться на текущей версии. Точная причина прежней ошибки workspace routing не установлена; специального обхода для Codex в коде нет.

Это фиксация выполненных исправлений, а не утверждение, что исправлены все дефекты проекта. Автоустановщик Self-hosted сохранён: его firewall/NAT требуют отдельной доработки. Автозапуск и сворачивание в трей пока остаются элементами интерфейса. Серверный протокол, частичная отправка TCP и обработка переполнения серверной очереди в этой версии не менялись.
