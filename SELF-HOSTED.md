# Self-hosted: исправления

- `SshService.cs`: проверка аргументов и требований сервера, тайм-ауты SSH/скачивания, SFTP при ошибке загрузки с сервера, проверка SHA-256 фиксированного релиза, ошибки вместо ложного успеха. Работа SSH вынесена с потока интерфейса.
- `setup-firewall.py`: внешний интерфейс из IPv4-маршрута; разрешение TCP/7777 и пересылки только подсети 172.16.0.0/24 в существующих базовых цепочках nftables; отдельный NAT Jammer. Чужие правила и политики сохраняются. Повторный запуск заменяет только свои правила.
- `install-server.sh`: резервная копия файлов и firewall, настройка forwarding, служба с ExecStartPre для восстановления правил при старте, проверки PID/порта/TUN. При ошибке установки восстанавливаются прежние файлы и ранее работавшая служба; полного отката всего firewall нет.
- `ServerProbe.cs`: проверка TCP/7777, ECDH/AES и реального UDP DNS-запроса к 1.1.1.1 через серверный TUN, forwarding и NAT. Адаптер и маршруты на компьютере не создаются. Успех выводится после правильного ответа.
- `SelfHostedView`, `GuiLogSink`: этапы и ошибки в прокручиваемом журнале установки; блокировка кнопки на время операции, маскирование SSH-пароля.

## Поддержка

Linux x86_64, root, systemd, /dev/net/tun, iproute2, nftables и Python 3. При отсутствии nftables/Python установщик использует apt-get на Debian/Ubuntu. Проверено на Ubuntu 24.04. Активные firewalld и legacy iptables отклоняются явно. UFW после его отдельной перезагрузки/перезаписи firewall может потребовать `systemctl restart jammer`; интеграция с его собственными конфигурационными файлами не добавлялась.

Правила восстанавливаются перед запуском Jammer; forwarding также записывается в `/etc/sysctl.d/99-jammer.conf`. После отдельного сброса/перезагрузки firewall нужно перезапустить Jammer. Полная перезагрузка VPS в рамках проверки не выполнялась.

Если проверка извне не проходит, установка не сообщает об успехе. При этом служба может уже быть установлена: сообщение об ошибке содержит этап. Внешние правила firewall провайдера этим установщиком не изменяются.

## Проверено

- В изолированных Linux network namespaces: TCP/7777, forwarding/NAT через две базовые цепочки с DROP, сохранение SSH-правила, отсутствие дублей при повторе, смена WAN-интерфейса, восстановление после сброса firewall/forwarding.
- На рабочем VPS: две последовательные установки этим C#-методом, определение нестандартного имени интерфейса, доступность TCP/7777 и успешный DNS-ответ через зашифрованный туннель; остальные службы остались активны.
- Локальная сборка Windows и проверки аргументов/встроенных ресурсов. SFTP-ветка не проверялась принудительным отказом GitHub; она остаётся резервным путём.

```powershell
dotnet run --project tests/SelfHosted.Checks -c Release
dotnet run --project tests/SelfHosted.Checks -c Release -- --probe SERVER_IPV4
```

Проверка firewall в одноразовых сетевых пространствах на Linux (нужны root, iproute2, nftables, Python 3 и ping):

```bash
sudo bash tests/selfhost-netns.sh
```

В журнал установки и публичные исходники SSH-пароль не записывается. Локальные backup-файлы остаются в `/opt/jammer/backups` сервера.
